# フェーズ6: 案Aへの移行（条件付き: フェーズ1で案Cを選んだ場合のみ）

目安: 半日。実施主体: メインセッション（コード削除は小規模なのでworktree委譲不要）。
本番反映はユーザー承認必須。

**このフェーズはフェーズ1で案Cを選んだ場合のみ実施する。案A/Bを選んだ場合はフェーズ5で完了。**

## ゴール

案Bの暫定パッチが `server.py` から削除され、本番がupstream準拠のper-user passthroughで
稼働している。`.claude/FORK-DELTA.md` から共有キーパッチのエントリが消えている。

## 着手トリガ

本番で使う**全クライアント経路（Claude Code / claude.ai / mcp-portal）で
`X-Portainer-API-Key` の注入が実機で確認できた時点**。新機能のリリース待ちではなく、
既存の設定手段で注入できることの確認をもって着手する。

**着手前に改めてplannerを呼び、その時点の状況でプランを更新すること。**

## タスク

1. 全クライアント経路でヘッダ注入が可能になったことを再確認する（フェーズ1タスク1と同じ方法）。
2. `server.py` から案Bの共有キー分岐（フェーズ2タスク3-5で入れたパッチ）を削除する。
   `docs/configuration.md` から対応するenv変数の記述も削除する。
3. `uv run pytest` 全件PASSを確認し、reviewerサブエージェントを通す。
4. フェーズ3と同じローカル検証を、案Aのenv構成で実施する。
5. ユーザー承認後、新しいフォークタグ（`hl-<version>-<rev+1>`）を打ってデプロイする。
   旧構成のenvとイメージダイジェストを切り戻し先として記録する。
6. `.claude/FORK-DELTA.md` から共有キーパッチのエントリを削除し、`.claude/ROADMAP.md` /
   `.claude/phases/*.md` に移行完了を記録してコミットする。
